\block{1. Problem, Context, and Users}{
  \takeawaybox{Addressing Water Losses \& Manual Billing Bottlenecks in Rwanda}

  \textbf{Context:} In Rwanda, WASAC and citizens face severe water management challenges. Non-revenue water losses exceed 38\%, caused by undetected pipe leaks and unmonitored communal taps.

  \begin{itemize}
    \item \textbf{Affected Users:} WASAC utility staff and residential households.
    \item \textbf{Bottlenecks:} Manual billing delays leak detection by weeks.
    \item \textbf{Solution:} AquaTrack provides automated IoT telemetry, real-time leak alerts, and dual web dashboards.
  \end{itemize}
}

\block{2. Objectives and Scope}{
  \begin{itemize}
    \item \textbf{Aim:} Build and evaluate an end-to-end smart water meter monitoring platform for WASAC.
    \item \textbf{Objective 1:} FastAPI simulator for 3 vendor standards: Kamstrup residential, Susteq communal taps, EoI prepaid meters.
    \item \textbf{Objective 2:} Node.js poller executing every 5 minutes to persist consumption deltas into PostgreSQL with automatic anomaly detection.
    \item \textbf{Objective 3:} Role-based portals for citizens and WASAC staff.
    \item \textbf{Scope:} Live Railway-hosted simulator + responsive web client.
  \end{itemize}
}

\block{4. Constraints \& Design Decisions}{
  \textbf{Database Architecture --- PostgreSQL + Sequelize ORM}
  \begin{itemize}
    \item \textbf{Relational Integrity:} Strict foreign-key constraints connect Households $\rightarrow$ Meters $\rightarrow$ MeterReadings $\rightarrow$ Alarms. A document store cannot enforce these guarantees natively.
    \item \textbf{Security:} Password hashing handled via Sequelize \texttt{beforeCreate} bcrypt hooks.
    \item \textbf{Trade-off:} Development used \texttt{sync(\{alter:true\})}; production requires structured migrations.
  \end{itemize}

  \vspace{0.3em}
  \textbf{FastAPI Meter Simulator (Railway Microservice)}
  \begin{itemize}
    \item Simulates 30 meters across 3 vendor protocols with diurnal usage curves (peaks at 06:00--09:00 \& 17:00--21:00).
    \item \textbf{Alarms:} Condition-triggered leak/high-usage alarms persist across 3--12 polls.
    \item \textbf{Backend Detection:} The Node.js poller automatically flags nighttime leaks and daytime consumption spikes using threshold-based anomaly detection.
  \end{itemize}

  \vspace{0.3em}
  \textbf{Authentication --- Stateless JWT}
  \begin{itemize}
    \item Two token keys enforce role separation: \texttt{aquatrack\_token} (WASAC staff) and \texttt{citizen\_token} (citizens).
    \item \textit{Trade-off:} Tokens cannot be invalidated before expiry without a blacklist --- acceptable for project scope.
  \end{itemize}
}

\block{5. Solution \& System Architecture}{
  \takeawaybox{End-to-End IoT Telemetry \& Microservice Architecture}

  AquaTrack bridges hardware telemetry and user dashboards via an automated 5-minute poller. The FastAPI simulator models hardware meters, the backend ingests readings into PostgreSQL, and Express REST APIs serve live analytics. The poller also runs real-time anomaly detection: nighttime leaks and daytime consumption spikes are persisted directly to the alerts table.

  \begin{itemize}

    \item Persistent alarms: leak (5--12 polls), burst (2--4 polls), high usage (3--6 polls).
